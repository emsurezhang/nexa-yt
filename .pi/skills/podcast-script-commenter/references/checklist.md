SKILL.md 里的六层检查在这里展开。点评时按需读取对应章节，不必全部照搬。

## 1. 事实与引语核查

AI 生成的脚本最容易在"具体细节"上出错，因为这些细节读起来最有说服力。逐项扫描：

| 检查项 | 常见问题 |
|---|---|
| 人名与头衔 | 名字拼写、人物所属公司、职位是否张冠李戴 |
| 出处 | "某人在某播客/某月说过"——播客名、月份、场合是否对得上 |
| 数字 | 金额、数量、排名、百分比：口径是什么（收入/定价/估值）？哪一年？谁统计的？ |
| "原话" | 翻译过的引语被当成原话；两个人的话被合并；断章取义 |
| 时间线 | 事件先后、"去年/上个月"是否与真实日期一致 |
| 因果断言 | "因为 A 所以 B"是来源说的，还是脚本自己推的？ |
| 绝对化表述 | "第一""唯一""从未""断层领先"——是否有依据 |

处理建议：

- 列出**需要核实的清单**，并说明每条为什么可疑（例如"这是一个精确数字，且没有给出口径"）。
- 引语建议改成"大意是……"，或附英文原句。
- 无法核实又不重要的细节，建议直接删掉或改成模糊但准确的说法（如"数百万美元"→"每年数百万美元量级"）。

## 2. 前后自洽

- **标题 vs 正文**：标题里的承诺（数字、结论、"怎么做"）正文是否兑现？例如标题写"$1M 年薪"，正文却从不解释这个价格从哪来。
- **开头 vs 结尾**：开头抛出的钩子结尾是否回扣？开头的说法是否被后文悄悄推翻？（例如开头说"岗位不存在"，后文解释成"没有统一定义"，二者就打架了。）
- **概念一致**：同一个概念在前后是否用了不同的叫法或不同的定义？
- **潜在矛盾**：不同嘉宾/来源的观点冲突时，脚本有没有交代调和方式？（例如一处说"全是从零写代码就是外包"，另一处说某团队"写代码极快"，需要补一句说明为什么不矛盾。）
- **列表数量**："三顶帽子""两个坑"这类数字，正文是否真的对得上？

## 3. 措辞与表述

- **标题党**：夸张说法（"根本不存在""全行业都错了"）后文是否兜得住？兜不住就改成准确版本。
- **暗含因果**：结果数据被写成主动决策（"敢收 400 万"暗示定价，实际是平均收入）。
- **会过期的相对时间**："上个月""今年七月""去年"——播出后就不准，建议写成具体年月。
- **概念混用**：先说"第一顶帽子"再说"三顶帽子"，听众容易糊涂，需要顺一下逻辑。
- **口语化 vs 书面语**：口播稿里出现长定语、括号补充、书面连接词，听起来会累。

## 4. 内容结构

- **有没有具体案例**：标题承诺"怎么做"的，正文是否只有概念？建议加一段 1–2 分钟的场景（可明确标注"假设一个场景"），把流程完整走一遍。
- **是否兑现标题**：标题里的卖点（价格、结果、方法）正文有无正面回答？
- **反面视角**：全篇一边倒正面时，补一小段风险、代价或局限（更可信，也更有信息量）。
- **信息密度**：单段是否塞了太多新名词/人名？建议每段只推进一个核心点。
- **结尾**：只保留**一个**行动号召；评论区问题要让大多数听众都能回答，而不是只有特定人群能答。
- **收束**：结尾是否用一句话回顾了主线？

## 5. 对话节奏（多人脚本）

- **谁在主导**：一个人长篇独白、另一个只负责"为什么？""然后呢？"，会变成一人讲课。让第二位说话人多表达立场：质疑、类比、总结、补充自己的经验。
- **独白长度**：单段超过约 150 字（中文）建议拆开，中间插入回应。
- **接话套路**：反复出现"对""问到点子上了""你别笑"等，建议替换或删除。
- **情绪标签**：同一种情绪（如 [laughing]）出现多次、且触发场景相似，会显得机械。减少或换成不同情绪。
- **打断与重叠**：适度的插话、追问、纠正更像真人对话。
- **信息量分配**：两人的话是否都在推进内容，而不是一人问、一人答的"访谈模板"。

## 6. TTS 适配

- **外文人名/术语/缩写**：Natalie Meurer、a16z、Foundry、DevOps 等，中文 TTS 容易读错。建议给发音提示，或改成中文读法（"a16z"→"安德森·霍洛维茨"）。
- **数字与符号**："$1M"→"一百万美元"；"2008 款"→"二〇〇八款"；百分号、斜杠、括号尽量改成口语。
- **情绪/语气标签**：确认所用 TTS 引擎是否支持这些标签，不支持会被直接念出来，或被忽略。
- **长句**：一句超过约 40 字建议拆短，方便换气。
- **同音/歧义字**：容易读错的多音字、易混淆的同音词，必要时加注音或换说法。
- **停顿控制**：需要停顿处用标点或引擎支持的停顿标记，而不是靠空格或省略号。
- **段落长度**：单条台词不宜过长，否则合成音色和语气会漂移。
