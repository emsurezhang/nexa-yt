# 1. 触发条件（何时使用本 Skill）

满足以下任一情况时，Agent 应调用本 Skill：

- 用户明确请求"选题"相关工作，例如："帮我策划下一期选题"、"给这期节目找个题目"、"生成选题与素材文档"。
- 用户提出了一个主题方向，但需要围绕它收集支撑素材（字幕/引用/观点）。
- 用户要求"从近期 YouTube 视频里看看有什么可以讲的"、"帮我看看最近有什么热点可以做"。
- 用户在筹备博客/播客节目的前期策划阶段，且尚未进入文案撰写或剪辑阶段。

**不适用场景**（应交由其他 Skill 或直接处理）：
- 用户已经给定完整的主题+提纲，只需要润色、扩写正文。
- 用户要求的是单纯的视频信息查询（如"这个视频讲了什么"），且并非用于选题策划目的。
- 涉及非 YouTube 来源的素材收集（本 Skill 当前只对接 YouTube 内容获取 Skill）。

# 2. 用户指定主题 vs 自主寻找主题的判断规则

Agent 需要先对用户输入做一次意图分类，依次判断落入以下三种情况中的哪一种：

情况一：用户指定模式。 当用户输入包含明确、具体的主题/问题/论点时（例如"聊聊 AI Agent 会不会取代产品经理"），Agent 应直接以该主题为核心，跳过选题发现环节，直接进入素材收集（第5节）。

情况二：约束式自主模式。 当用户只给出了宽泛领域或范围，而非具体论点时（例如"科技类"、"聊聊 AI 相关的"、"某频道最近的内容"），Agent 应将其作为筛选范围或关键词约束，在该范围内自主发现具体主题（第3节），再进入素材收集。

情况三：自主发现模式。 当用户完全没有给出任何方向时（例如"帮我找个选题"、"最近有什么可以做的"），Agent 应完全自主发现主题（第3节）

# 3. 自主寻找主题的方法

当进入"自主发现"或"约束式自主"模式时，按以下步骤执行：

1. **轻量扫描**：调用 YouTube 内容获取 Skill 的「搜索」能力（若用户给出范围/关键词）或「指定频道内容获取」能力（若用户指定了频道/信任源），只获取 **title（+ description，若搜索接口提供）**，不获取详细信息。
2. **候选排序**：基于以下信号对扫描到的标题进行打分排序：
   - 发布时间新近度（越新权重越高）；
   - 标题体现的话题独特性/争议性/热度；
   - 与 Nexa 博客定位的契合度（定位描述需在使用前明确，若未提供则按"泛科技/AI/创业"通用方向处理，用户可在调用时覆盖此定位）；
   - 是否与近期已产出过的选题重复（如有历史选题记录，应避免重复）。
3. **生成候选主题**：从排序结果中提炼出 2–3 个候选主题，每个附带一句话理由（源自哪些标题、为什么值得做）。
4. **确定最终主题**：
   - 若处于可与用户交互的场景，向用户展示候选供确认；
   - 若要求一次性产出（无交互），默认选取排序最高的候选作为最终主题，其余候选记录在文档的备选项中（可选）。

# 4. 与 YouTube 内容获取 Skill 的联动方式

约束：本 Skill 不直接访问网络或 YouTube API，所有与 YouTube 相关的信息都必须通过调用 nexa-yt 提供的能力获得，不得凭空假设或编造视频内容。nexa-yt 的具体调用方式（命令、参数、鉴权、限流策略等）由其自身 Skill 定义负责，本 Skill 只需按需调用、按约定使用返回结果，不重复声明其实现细节。

### 4.1 四种能力与本 Skill 各阶段的映射
关键词搜索：返回粒度为标题 + 描述（通常不含字幕）。用途包括：① 自主选题阶段的候选广度扫描；② 素材收集阶段获取候选素材的摘要信息（对应 5.1）。
频道扫描：返回粒度为标题（描述等完整字段可能缺失）。用途包括：① 针对用户指定/信任频道做定向扫描以发现主题；② 素材收集阶段对该频道近期内容做摘要级筛选。
单视频详情：返回粒度为完整信息（含描述、字幕等）。用途为：仅在摘要阶段判定"高相关"或"待定"后，针对具体候选视频调用，获取详细内容/字幕用作最终素材引用。
订阅频道管理：返回粒度为订阅配置（url/alias/max_results/enabled）及订阅频道视频列表。用途包括：① 维护信任频道清单（新增/启用/停用订阅），使"信任源"可沉淀复用；② 通过 `videos` 按 alias 直接获取订阅频道近期视频列表，等效于频道扫描单频道，但不更新增量游标，适合"约束式自主模式"下对信任源做定向扫描。

### 4.2 调用顺序原则（由轻到重）
先用「关键词搜索」或「频道扫描」（若频道已在订阅清单中，优先用「订阅频道管理」的 `videos`/`list` 按 alias 调用）拿到摘要级信息，形成候选素材池；
仅对通过相关性初筛（见第5节）的候选，才调用「单视频详情」补抓完整信息；
不对未通过初筛的候选调用详情能力，避免不必要的调用成本。

### 4.3 异常情况的基本处理原则
若部分候选缺少摘要信息（如描述为空），按现有信息尽力判断，不视为流程失败；
若调用能力本身失败或不可用（如鉴权失效、限流等），应如实告知用户当前无法获取相关信息，而非静默跳过或编造结果；
素材摘录必须来自真实返回内容，不得在没有调用详情能力的情况下编造字幕或描述文本。

# 5. 素材与主题的关联性判断流程

### 5.1 获取摘要信息
对主题相关关键词/已确定主题，调用「搜索」或「指定频道内容获取」，得到一批候选素材的 **title（+ description）**，形成候选列表，此阶段不做深入判断，只做粗筛（如去重、去掉明显不相关领域的结果）。

### 5.2 判断是否需要获取详细信息
对候选列表中的每一条摘要，与主题做语义匹配判断，判断依据包括：
- 标题/描述中是否包含主题关键词或紧密相关的子话题；
- 标题/描述所暗示的观点/立场是否与主题的讨论方向相关（而非仅字面关键词重合）；
- 是否为"标题党"型内容（标题看似相关但描述明显文不对题）。

设定一个相关性判断结果为三档：**高相关 / 待定 / 不相关**。
- 高相关 或 待定 → 进入 5.3，调用「指定视频内容获取」拿详情；
- 不相关 → 直接排除，不再消耗详情调用配额。

### 5.3 过滤不相关的详细信息
获取到 full detail（含字幕）后，进行二次核查：
- 核实视频实际内容是否真正支撑主题（而不仅是标题层面的关联）；
- 提取与主题直接相关的片段/引用，作为素材摘录；
- 若详情核查后发现实际内容偏离主题，予以剔除，并可记录剔除原因（用于文档透明度，便于用户复核选题逻辑）。

最终只有"标题摘要初筛通过 + 详情核查确认相关"的素材，才进入输出文档的正式素材列表。

# 6. 输出格式（JSON）

```json
{
  "topic": {
    "title": "主题标题",
    "description": "对该主题的简要说明，包括核心问题/论点",
    "source": "user_specified | auto_discovered",
    "rationale": "若为 auto_discovered，说明选择该主题的理由；若为 user_specified 可留空或简述用户原始表述",
    "alternative_candidates": [
      {
        "title": "备选主题标题",
        "reason": "未被选中但值得记录的理由"
      }
    ]
  },
  "materials": [
    {
      "video_id": "视频唯一标识",
      "video_title": "视频标题",
      "channel": "频道名称",
      "published_at": "发布时间(ISO8601)",
      "url": "视频链接",
      "source_stage": "search | channel | video_detail",
      "relevance_level": "高相关 | 待定通过",
      "relevance_summary": "该素材为何与主题相关的简述",
      "relevant_excerpts": [
        "从字幕或详情中直接复制的原始片段，禁止概括、改写、翻译或润色；保持原文语言（英文素材保留英文）；"
      ]
    }
  ],
  "excluded_candidates": [
    {
      "video_title": "被排除的候选视频标题",
      "excluded_at_stage": "summary_filter | detail_filter",
      "reason_excluded": "排除原因，便于复核"
    }
  ]
}
```

**字段说明补充**：
- `materials` 仅包含最终通过完整判断流程（5.1→5.2→5.3）确认相关的素材。
- `excluded_candidates` 为可选字段，用于保留选题过程的透明度，便于用户复核 Agent 的筛选逻辑，非必须输出但建议保留。
- `topic.source` 用于追溯该主题是用户直接指定还是 Agent 自主发现，便于后续复盘选题策略的有效性。
