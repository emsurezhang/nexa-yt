## 工作过程规则
1. 工作过程仅使用SKILL当中定义的工具；不允许编写程序生成自定义工具；

## 任务工作目录隔离规则
你在执行每一个独立任务时，必须遵循以下文件系统操作规范：

### 1. 任务区分规则
1. **新任务判定**：当用户发起全新的业务请求、全新目标、全新的工作指令，视为一个**新任务**。
2. 同任务：同一个对话上下文内，对同一个原始任务进行追加修改、补充子步骤、迭代调试，属于**同一个任务**，复用同一个任务文件夹。
3. 任务边界：
   - 用户更换完全不一样的目标、全新需求、全新问题 → 触发新任务，新建独立文件夹。
   - 仅对已有任务做修改、复盘、二次处理、调试，不新建文件夹，继续使用原有任务目录。
4. 任务ID生成：每个新任务生成唯一任务标识task_id，用于文件夹命名。

### 2. 文件夹命名规范
1. 根目录固定：`./data/`，所有任务子文件夹必须创建在该目录下。
2. 文件夹命名格式：`task_{时间戳}_{简短任务摘要}`
   - 时间戳：使用UTC时间戳，格式`YYYYMMDD_HHMMSS`，例如`20260909_143022`
   - 简短任务摘要：用英文小写，下划线分隔，不超过32字符，概括任务核心目标，禁止特殊字符、空格、斜杠。
   - 示例：`task_20260909_143022_data_process_csv_analysis`
3. 禁止使用中文、空格、`/ \ : * ? " < > |` 等非法路径字符。
4. 如果`./data`目录不存在，**首先自动创建 ./data 目录**，再创建任务子文件夹。

### 3. 文件存放强制约束
1. 该任务产生的**全部临时文件、中间产物、缓存、下载文件、中间输出、调试日志、临时脚本**，必须全部存放在该任务子文件夹内。
2. 禁止把任务临时文件写到当前工作目录、`./`根目录、其他任务文件夹。
3. 任务完成后，不要自动删除任务文件夹，保留所有任务产物便于后续复盘。
4. 执行文件操作前，先确认目录路径，避免路径错误。

### 4. 执行流程（Agent必须严格按顺序）
当接收到一个新任务：
1. 判断是否为新任务；
2. 生成唯一task_id（时间戳+简短摘要）；
3. 确保`./data`存在；
4. 创建目录 `./data/task_{时间戳}_{简短任务摘要}`；
5. 后续本任务所有临时读写操作，全部限定在这个目录内；
6. 可以在回复中告知用户本次任务的工作目录路径，方便用户查看文件。

### 5. 例外情况
仅当用户明确指定输出路径时，才按照用户指定路径保存最终结果；**但中间临时文件仍然必须放在任务专属子文件夹内**。
